# Agent Note：为窗口的排布命名

Status: implemented

[English](2026-09-02-window-arrangement-preference.md) | 中文

## Problem

桌面窗口的每一条接缝都变得可拖动，这让布局可调，也让它难以被发现：要得到一个「工作空间优先」的窗口，意味着收起会话侧栏并把对话列拖到下限；而重新加载之后要再得到它，就意味着再做一遍这两件事。面板几何是有意做成瞬态的 —— 拖出来的宽度不会在重新加载后留存 —— 因此并不存在一个可以回到的排布，只有需要重做的宽度。

## Decision

**排布是偏好；它产生的宽度不是。** 四种具名排布 —— `balanced`、`workspace`、`conversation`、`everything` —— 存放在持久的 `ui-layout` 设置分区中，而它们各自写入的宽度仍是瞬态的。重新打开应用会恢复读者选择的排布，而不是他们随手推过一次的几何。这条规则一句话就能说清，这正是它值得被采用的原因。

## Alternatives considered

**直接持久化宽度本身。** 否决，尽管这是显而易见的做法。面板几何在设计上就是瞬态的，而在有人伸手够别的东西时随手拖出的一个宽度，被重新加载恢复出来，比恢复一个他们有意命名过的形状更糟。

**preset 作为一次性动作，不存储任何东西。** 否决：重排窗口之后在重新加载时丢失它，正是问题本身，而不是解决方案。

**preset 作为锁定各列的模式。** 否决。接缝在上一个 commit 才刚刚变得可拖动；用它去换一个名字是笔糟糕的交易。

**preset 写入的是偏好，而不是解析后的轨道。** 它设置的正是拖动会设置的那些宽度偏好，因此 concession 链的回应完全一致：索取超过窗口所能提供的排布，会按这些宽度一贯的方式做出让步，而任何 preset 都无需知道窗口的尺寸。

**此后的拖动不会改写排布的名字。** preset 是布局的起点，而不是它此后停留的模式。在第一次拖动时就清空名字，会让设置行什么都不显示，而这比一个略微陈旧的名字说明得更少。

**选择先重排，然后才持久化。** 窗口在选择它的同一次手势中移动；写入 Host 是随后发生的事。而**从** Host 采纳的排布会被应用但不写回，这正是它能挺过它所服务的那次重新加载的原因。

## Consequences

`ui-layout` 增加了一个 Host 半边。它此前没有 —— `apply` 是有意的空实现 —— 现在它与其他每个包一样注册持久分区，因此排布与用户的其余偏好存放在同一份文档中，而不是这个浏览器自己的存储里。

store 在宽度之外持有 `preset`，因此设置行与各 frame 读取同一个来源。插件主体保持轻薄：`bindLayoutPreference` 拥有「跟随并应用」的逻辑，这正是它无需 slot registry bench 就能被测试的原因。

`packages/client/ui-layout/src/*` 带有既有的覆盖率豁免，因此新文件不受逐文件阈值约束。它们仍然被测试 —— 偏好绑定、preset 几何、store action 与设置行各有自己的用例。

## Testing

偏好绑定被直接覆盖：构造前发布、采纳但不写回、忽略不产生变化的已接受分区、对重复选择重新应用（因为此后窗口可能已被拖动过），以及在 dispose 后停止跟随。几何测试断言每种排布都是不同的窗口，并且以某一列命名的两种排布确实把最多的空间交给了它 —— 这是通过桌面求解器测量的，而不是比较 preset 中所写的数字。
